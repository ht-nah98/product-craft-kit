## Mục Đích

Skill này hướng dẫn thực hiện Phase 4 "DELIVER" - giai đoạn build MVP, ship to users, và learn from real usage.

### Goals của Phase này:
- ✓ Build MVP theo shaped solution
- ✓ Ship to real users (internal hoặc beta)
- ✓ Collect feedback và metrics
- ✓ Learn và validate/invalidate assumptions

**OUTPUT**: Shipped MVP + Initial learnings

## Quy Trình Thực Hiện

### Bước 1: Build Kickoff

**Kickoff Meeting Agenda:**
1. Review shaped solution với team
2. Clarify scope boundaries (no-gos)
3. Discuss technical approach
4. Identify first tasks
5. Set daily standup rhythm

**Key Principles:**
- Team owns implementation details
- Scope can be hammered further
- Ship early, ship often (dogfooding)

### Bước 2: Development Cycle

**Hill Chart Tracking:**
- **Uphill**: Figuring things out (unknowns → knowns)
- **Downhill**: Executing (known work)

Track progress visually, focus on getting over the hill.

**Daily Rhythm:**
- Short standup (15 min)
- Focus on blockers
- Demo frequently (internal)

### Bước 3: Launch Preparation

**Pre-Launch Checklist:**
```
Technical:
□ Core functionality working
□ Error handling in place
□ Logging và monitoring setup
□ Performance acceptable
□ Security review done

User Experience:
□ Onboarding clear
□ Help/documentation ready
□ Feedback mechanism in place
□ Known limitations documented

Operations:
□ Rollback plan ready
□ Support team briefed
□ Escalation path clear
□ Success metrics tracked
```

### Bước 4: Launch Strategy

| Launch Type | Audience | Purpose |
|-------------|----------|---------|
| Dogfood | Internal team | Find obvious bugs |
| Alpha | 5-10 trusted users | Deep feedback |
| Beta | 50-100 users | Scale testing |
| GA | All users | Full release |

**Recommended approach:**
1. Dogfood 1 week
2. Alpha 1-2 weeks
3. Beta/GA based on learnings

### Bước 5: Collect Learnings

**Quantitative:**
- Track success metrics (defined in Phase 2)
- Compare against baseline
- Monitor guardrail metrics

**Qualitative:**
- User interviews (5-10 users)
- Feedback forms
- Support tickets analysis
- Observe usage patterns

**Key Questions:**
- Did users achieve their goal?
- What confused them?
- What did they love?
- What's missing?

---

## Ship to Learn Mindset

> "Real learning starts after users interact with your product"

**Common mistakes to avoid:**
- Waiting for "perfect" before shipping
- Ignoring negative feedback
- Measuring vanity metrics
- Not talking to users post-launch

**What to do:**
- Ship minimal version ASAP
- Embrace negative feedback as gifts
- Focus on leading indicators
- Schedule user conversations

---

## Completion Checklist

```
□ MVP built according to shaped scope
□ Internal testing (dogfood) completed
□ Alpha/beta launched to real users
□ Feedback collection mechanism active
□ Success metrics being tracked
□ Initial learnings documented
□ Bugs/issues triaged
□ Team retrospective done

GATE QUESTIONS:
□ Did users actually use it?
□ Did it solve the problem (even partially)?
□ What surprised us?
□ Should we continue, pivot, or kill?
```
