# Skill: Viết PRD (Product Requirements Document)

> Tuân thủ 100% template này khi viết PRD

---

## Trước khi viết

1. **Đọc project context**: `projects/[project]/project-context.md`
2. **Thu thập thông tin từ user**:
   - Problem statement
   - Target users
   - Business goals
   - Constraints/limitations

---

## Cấu trúc PRD chuẩn

### 1. Template Location
> **Template File**: [`_master/templates/01_business_docs/_template_prd.md`](../../templates/01_business_docs/_template_prd.md)

### 2. Cấu trúc PRD

1. **Overview**: Problem statement & Solution (Quan trọng nhất)
2. **Goals/Non-Goals**: Scope definition
3. **User Stories**: Functional requirements overview
4. **Requirements**: Functional & Non-functional details
5. **Timeline**: Milestones


---

## Quy tắc viết PRD

### 1. Audience-First
- Viết cho người đọc (dev, designer, stakeholder)
- Không giả định người đọc đã biết context
- Define terms/acronyms

### 2. Why Before What
- Luôn giải thích TẠI SAO trước khi mô tả WHAT
- Problem statement là phần quan trọng nhất

### 3. Measurable Success
- Mỗi goal phải có metric đo lường
- Tránh mục tiêu mơ hồ như "improve UX"

### 4. Clear Scope
- Goals và Non-Goals phải rõ ràng
- Tránh scope creep bằng cách define rõ out of scope

---

## Checklist trước khi hoàn thành

- [ ] Problem statement rõ ràng
- [ ] Success metrics đo lường được
- [ ] Goals và Non-Goals defined
- [ ] User personas identified
- [ ] User stories có đủ detail
- [ ] Functional requirements listed
- [ ] Non-functional requirements defined
- [ ] Timeline realistic
- [ ] Open questions tracked
- [ ] Stakeholders đã review
